# IsaacLab — Benchmark Guide

Generated by `benchmark-generator` skill. English-only by contract; regenerated on every re-run.

## About

Isaac Lab is NVIDIA's open-source robot-learning framework built on top of Isaac Sim. It provides a GPU-vectorized RL environment factory (200+ registered Gymnasium IDs spanning classic control, dexterous manipulation, locomotion, navigation, factory/assembly, and visuomotor stacking) plus an integration layer for popular RL libraries (rl_games, rsl_rl, skrl, stable_baselines3). The simulator runs on PhysX 5 with the RTX renderer; envs typically execute at 30–120 control Hz with `num_envs` in the thousands.

| Field | Value |
|-------|-------|
| Simulator | NVIDIA Isaac Sim 4.5.0 (PhysX 5 + RTX, GPU-vectorized) |
| Benchmark category | **RL** |
| Upstream paper / project | https://github.com/isaac-sim/IsaacLab — Mittal et al., *Orbit: A Unified Simulation Framework for Interactive Robot Learning*, IEEE RA-L 2023 |
| License | BSD-3-Clause (see `LICENSE`) |
| Primary use case | Massively-parallel RL training for robot manipulation, locomotion, and dexterous control on a single NVIDIA GPU |

### Task groups

- **Direct envs** (`*-Direct-v0`) — single Python class subclassing `DirectRLEnv`; reward / observations / actions are all coded inline. Faster to extend, less configuration overhead.
- **Manager-based envs** (no `-Direct-` infix) — composed from reusable managers (action / observation / event / reward / termination). Recommended pattern for production.
- The wider repo also exposes `*-Showcase-*` variants (Cartpole with Box / Discrete / MultiDiscrete / Tuple / Dict spaces) and `*-Camera-*` variants for visuomotor work — see `python scripts/environments/list_envs.py` for the full list.

## Action / Observation spaces

Isaac Lab is GPU-batched, so all of these are `torch.Tensor` (NOT numpy ndarrays) of shape `(num_envs, ...)` on `env.unwrapped.device`.

| Field | Value |
|-------|-------|
| Action dim | task-dependent (e.g. Cartpole-Direct: 1; Reach-Franka: 7; Velocity-Flat-Anymal-C: 12) |
| Action semantics | continuous joint-position / joint-velocity / joint-effort targets in `[-1, 1]` (scaled internally by the action manager) |
| Observation type | `torch.Tensor` (default `policy` group); some tasks expose `Dict` obs with multiple groups |
| Control frequency | 30–120 Hz depending on task (`decimation` × `physics_dt`); Cartpole-Direct = 60 Hz, Velocity-Flat-Anymal-C = 30 Hz |
| Reward signal | dense per-step reward returned as `torch.Tensor` of shape `(num_envs,)`; reward is the sum of named reward terms registered via the reward manager |

## How to use

`benchmark-generator` provides only the env-sanity layer here: a random-action rollout (`scripts/run_random.py`) and an offscreen render-to-MP4 (`scripts/render_random.py`). For training / evaluation / hyperparameter tuning, see `rl-integration.md` (rendered separately by `rl-integration-generator` after `/rl-experiment setup`). For env build instructions, see `install.md` (env-generator's output).

### 1. Activate the venv AND source Isaac Sim env vars

This is the single biggest quirk in Isaac Lab: the venv on its own cannot resolve `import isaacsim` / `import pxr` / `import omni.kit`. You MUST source `_isaac_sim/setup_conda_env.sh` (despite the name, it works from a uv-managed venv too). Do this at the start of every shell:

```bash
unset CONDA_PREFIX CONDA_DEFAULT_ENV   # in case a stale conda env is leaking
source .venv/bin/activate
source _isaac_sim/setup_conda_env.sh   # sets CARB_APP_PATH, EXP_PATH, ISAAC_PATH and chains setup_python_env.sh
export OMNI_KIT_ALLOW_ROOT=1           # only needed if you ever run as root
```

You can also use `./isaaclab.sh -p <script.py> [args]` BUT only after `source _isaac_sim/setup_conda_env.sh` — the `-p` flag itself does not source those vars (verified during this run).

### 2. Pick a task

```bash
python -u scripts/environments/list_envs.py            # full list (200+ envs)
python -u scripts/environments/list_envs.py --keyword Cartpole   # filter
```

Any identifier from the task table above (or the `list_envs.py` output) is a valid value for `--task`.

### 3. Sanity-check the env (random rollout)

`scripts/run_random.py` runs N random-action steps, samples actions as `torch.Tensor` on the env device, and confirms each `env.step(...)` returns a finite numeric reward. No policy, no checkpoint, no rendering.

```bash
python -u scripts/run_random.py --task Isaac-Cartpole-Direct-v0 --n-steps 10
```

Expected last line:

```text
L1 OK: 10 steps, all rewards finite
```

The `python -u` is important — Isaac Sim's Kit logger floods stderr during startup (~20 s), so without unbuffered output the `step N: reward=...` lines are invisible until program exit.

### 4. Render a video of a random rollout

`scripts/render_random.py` runs the same rollout but with cameras on. It programmatically sets `args_cli.enable_cameras = True` so Kit picks the `isaaclab.python.headless.rendering.kit` experience (RTX renderer + offscreen viewport) and `env.render()` returns RGB frames.

```bash
python -u scripts/render_random.py --task Isaac-Cartpole-Direct-v0 \
    --n-steps 60 --output /tmp/IsaacLab_random.mp4
```

Open the resulting MP4 (`vlc`, `ffplay`, etc.) — you should see random-action behavior on the simulator. Cartpole-Direct produces ~63 KB/frame; expect ~4 MB for a 60-step clip.

### 5. Headed visualization

If you have `$DISPLAY` set, run with `--headless False` (or simply call `./isaaclab.sh -p scripts/<your_script>.py` from a graphical shell — the default is non-headless). The smoke scripts shipped here force `--headless` because they're designed for unattended CI.

## Troubleshooting

- `ModuleNotFoundError: No module named 'isaacsim'` → you forgot `source _isaac_sim/setup_conda_env.sh`. The venv alone is not enough.
- `ModuleNotFoundError: No module named 'pxr'` → same fix as above; `pxr` ships with the Isaac Sim binary, not the venv.
- `KeyError: 'EXP_PATH'` raised inside `AppLauncher.__init__` → `setup_conda_env.sh` was not sourced (it sets `EXP_PATH=$_isaac_sim/apps`). Re-source it.
- `RuntimeError: Failed to find an articulation when resolving '/World/envs/env_0/Robot'` → the task's robot USD references a Nucleus URL the Isaac Sim binary cannot fetch (offline + version mismatch). Common for the 3 FAIL tasks above. Either upgrade `_isaac_sim` to 5.0 or mirror the asset locally.
- Smoke output looks empty / hangs → run with `python -u`. Kit's logger output dominates the buffer.
- L2 produces `no RGB frames captured` → make sure `enable_cameras=True` (the script does this; if you're calling AppLauncher yourself, set it BEFORE the launcher).
- GPU not detected → check `nvidia-smi` from outside the script first; Isaac Sim picks the first NVIDIA GPU and skips AMD/integrated GPUs (verified on the host).
- `OMNI_KIT_ALLOW_ROOT` warning → harmless, only matters when running as root.
